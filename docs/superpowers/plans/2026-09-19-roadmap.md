## 1. 开发顺序原则

1. 不按 UI 页面顺序开发，按**依赖关系**开发。
2. 每个 Phase 结束时必须留下**可运行、可验证**的产物；不允许"半截状态"。
3. UI 先用 Mock Data 定型，再接真实数据源，避免功能实现推翻 UI 与数据模型。
4. WebSocket 不在早期引入：先用 HTTP 轮询把指标跑对，再换流式通道。
5. Agent 相关阶段（Phase 4/5）之前必须完成安全基线（配对 + Token），不允许"先裸奔后加鉴权"。

## 3. Phase 明细

### Phase 0 — 工程基础（详细计划已就绪）

**计划文件：** [2026-09-19-phase0-kmp-foundation.md](./2026-09-19-phase0-kmp-foundation.md)

内容：工具链与版本矩阵锁定（**已实测：Temurin JDK 25.0.4.1+1、Gradle 9.5.0、platforms/android-37.0、build-tools 37.0.0，原始工程 assembleDebug 通过**）、monorepo 结构、KMP + Compose Multiplatform 模块、架构骨架（`domain` / `data` / `core`）、PC 状态机（纯逻辑 + 测试）、网络与存储抽象、导航骨架、主题基础、CI。

**完成标准：** `./gradlew :composeApp:testDebugUnitTest` 通过；真机/模拟器可启动 App 并进入空 Dashboard 骨架页。

### Phase 1 — Design System + Mock UI（详细计划已就绪）

**计划文件：** [2026-09-19-phase1-design-system-and-mock-ui.md](./2026-09-19-phase1-design-system-and-mock-ui.md)

内容：Design Tokens、AppTheme（6 套强调色）、WidgetSurface（Glass / Solid / Minimal）、**Power Rail（环形主按钮 + 双行次级动作 + 连接条）**、Dashboard Mode 全部卡片（含品牌条、透视装饰文案、引用卡）、Monitor Mode 全部卡片（Quick Actions、环形进度、System Temps/Fans、Recent Activity）、**StandBy 时钟模式**、60 秒 Ring Buffer、三态切换手势、**响应式断点**、Settings Workspace 左导航外壳、Device Setup 表单（含 MAC/IP 校验）、Appearance 模块与 Live Preview。全部使用 Mock Data。

**完成标准：** 五个屏幕（Home Dashboard、PC Monitor、StandBy、Device Setup、Wallpaper & Personalization）视觉达成概念图 80–90%；关键纯逻辑（Ring Buffer、MAC 校验、断点、状态归约）有单元测试；Power Rail 各状态与连接条术语在 Compose UI 测试中被逐个断言；逐屏差异清单落在 `docs/plans/phase1-visual-review.md`。

### Phase 2 — 设备系统

**计划文件：** [2026-09-20-phase2-device-system.md](./2026-09-20-phase2-device-system.md)（计划期已定案：**DataStore Preferences + kotlinx-serialization JSON**，选型理由与备选对比见该计划 §0）

`PcDevice` 持久化、Add/Edit/Delete、Default PC、设备选择器、连通性测试（TCP 探测 + `GET /api/v1/status`）。

**完成标准：** 冷启动后设备列表与默认设备正确恢复；无 Agent 时连通性测试给出明确失败原因而非静默失败。

### Phase 3 — WOL

**计划文件：** [2026-09-20-phase3-wol.md](./2026-09-20-phase3-wol.md)（魔包纯函数 + `WakeOnLanSender` 接口/androidMain 实现 + `WakeSequence` 虚拟时间编排；真 PC 的 10/10 验收由用户执行）

`WakeOnLan` 接口 + Android 实现、魔法包字节构造、UDP 广播、3 次重试、MAC/广播地址校验、`WAKING → ONLINE/OFFLINE` 状态流转。

**完成标准：** 真机对目标 PC 连续 10 次开机成功；魔法包字节序列有单元测试（6×`0xFF` + 16 次 MAC）。

### Phase 4 — PC Agent（依赖 Q1 决策）

**计划文件：** [2026-09-20-phase4a-pc-agent.md](./2026-09-20-phase4a-pc-agent.md)（Agent 服务端：status / power / actions / 配对与 Token / Windows 服务自启；手机端接入另开 Phase 4B 计划）

**手机端计划：** [2026-09-20-phase4b-app-agent-integration.md](./2026-09-20-phase4b-app-agent-integration.md)（配对 UI、Keystore 存 Token、真实电源动作、存在性轮询）

项目骨架、HTTP 服务、`/status`、心跳、`/power/{sleep,shutdown,restart,lock}`、开机自启服务、配对、Token 鉴权。

**完成标准：** 手机端四种电源操作全部生效；未携带 Token 的请求返回 401；`/actions/{id}` 对未知 id 返回 404 且不执行任何外部命令。

### Phase 5 — PC Monitor 实时化

**拆成三份计划**（服务端 / 手机端 / 流式各一份，理由与 Phase 4A/4B 的切法一致：能单独验收、单独回滚）：

- **Phase 5A（已完成）**：[2026-09-20-phase5a-agent-metrics.md](./2026-09-20-phase5a-agent-metrics.md) —— Agent 的 `GET /api/v1/system`（spec §8 全部指标、Bearer 鉴权、取不到就 `null`、Windows 走 LibreHardwareMonitor 0.9.6）。
- **Phase 5B（待做）**：手机端 2 秒轮询 `/api/v1/system` + Monitor 实时化（身份卡/指标卡/温度风扇/网络/运行时长真数据、Ring Buffer 喂 sparkline、离线回退与可读原因）。
- **Phase 5C（待做）**：`/ws/v1/metrics` 流式通道、ACTIVE 1s / IDLE 5s 自适应、断线自动重连。

**完成标准：** 手机显示值与 PC 任务管理器/监控工具读数一致（CPU 负载 ±3%、温度 ±2℃）；拔网线 30 秒内自动恢复。

### Phase 5.5 — Quick Actions（V1.1）

Action 注册表、Agent 白名单、`POST /api/v1/actions/{id}`、Quick Action UI。

### Phase 6 — StandBy 集成

天气（30 分钟刷新、当前温度/天气/高低温/位置/未来 4 小时）、Android Calendar Provider 读取、Local Todo（Room）。

### Phase 7 — Personalization

内置壁纸 + 自定义壁纸（Photo Picker，持久化 URI）、强调色、Widget 风格、透明度、字号缩放、布局预设、Live Preview。

### Phase 8 — 显示与可靠性

Keep Screen On、横屏、沉浸式全屏、Idle 检测与自动调光、触摸恢复、Pixel Shift、Agent 重连、网络恢复、错误处理，最后执行 24 小时稳定性测试。

## 4. 依赖关系

```
Phase 0 ─► Phase 1 ─► Phase 2 ─► Phase 3 ─┐
                                          ├─► Phase 4 ─► Phase 5 ─► Phase 5.5
                                          │
         Phase 1 ─────────────────────────┴─► Phase 6 ─► Phase 7 ─► Phase 8
```

- Phase 2 依赖 Phase 0 的数据模型与存储抽象。
- Phase 3 只依赖 Phase 2，**不依赖 Agent**（这是能最早验证的真实链路）。
- Phase 4 依赖 Phase 2（设备地址）与安全基线。
- Phase 6/7 只需要 Phase 1 的 UI 骨架，可与 Phase 4/5 并行推进。
